# Bruce Arsenal 1.16.1 and BLE Stability Design

## Goal

Move Bruce Arsenal from its 1.2.0 base to official Bruce 1.16.1 while preserving the Arsenal module and board support, then fix the reported BLE discovery and exit/reboot failures on the LilyGo T-Embed CC1101.

## Scope

- Merge the upstream `pr3y/Bruce` 1.16.1 source and board changes into this fork.
- Preserve Arsenal-only modules, build integration, documentation, and board environments that are not present upstream.
- Resolve shared-file conflicts by keeping upstream lifecycle, memory, and hardware fixes unless the fork has a required Arsenal integration point.
- Make BLE discovery use one stable NimBLE scan callback, active scanning, duplicate reporting, bounded display storage, and deterministic cleanup.
- Show advertised names when present, retain the address as the fallback label, and keep the detail view's name/address/RSSI values consistent.
- Ensure BLE scan and BLE spam exit paths stop scanning, clear results, and release the BLE stack before returning to the menu.
- Keep the T-Embed CC1101 build and flash flow reproducible through PlatformIO and the existing GitHub Actions workflows.

## Non-goals

This change does not add or extend victim-targeted MAC impersonation, evil-twin/captive-credential capture, WPS exploitation, hidden-network disclosure, BLE disruption, or other new offensive actions. Existing modules are updated only where required for compatibility, stability, and device discovery.

## Architecture

The upstream merge is the first layer. It supplies the 1.16.1 core, board definitions, library versions, and official BLE/Wi-Fi lifecycle changes. Arsenal remains an isolated source subtree and is reconnected through the existing PlatformIO source filter and menu integration.

BLE discovery remains synchronous from the UI's perspective. `ble_scan_setup()` owns initialization and callback registration. `ble_scan()` owns scan execution, result-to-menu conversion, and a single cleanup path. Cleanup is idempotent so escape, scan errors, and normal completion cannot leave the controller or callback state live.

## Error handling and resource rules

- A missing scan object or insufficient RAM returns to the menu with an actionable display error.
- A null advertised-device result is skipped.
- A missing name becomes `<no name>` in details and uses the address as the menu label.
- The scan result list is bounded by the upstream display limit.
- Scan results are stopped and cleared before BLE deinitialization.
- BLE deinitialization is attempted only when no managed BLE client/server remains active.
- No new heap-owning callback object is created per scan.

## Verification

- Reproduce the existing T-Embed build and record the baseline failure/success.
- Build `lilygo-t-embed-cc1101` after each shared-source slice and after the final merge.
- Build the official CI-selected environment set when time and dependency cache allow.
- Flash the final T-Embed image to the connected `/dev/ttyACM0` device using PlatformIO.
- Capture serial boot output and manually exercise BLE scan, back, and BLE spam exit paths on hardware.
- Confirm repository status, commit sequence, pushed branch, and GitHub Actions result before handoff.
